## Definition of done
A task is done only when ALL of these hold:
1. `bash scripts/verify.sh` passes
2. You ran the `verify` skill and checked the evidence it produced (screenshots, output, logs)
3. Every verification scenario in the ticket is checked off with evidence (test name or evidence path)
4. The `ponytail-review` skill finds nothing left to fix, and the `reviewer-correctness` agent returned APPROVE

Never weaken, skip, or delete a test or eval case to get green. If a test looks wrong, stop and say why.

## Skills in this repo
- `setup-factory`: fills in this file and the scripts for a new or existing project
- `write-ticket`: turns a description into a ticket in `tickets/`
- `feature`, `fix-bug`: the main workflows
- `merge-pr`: merges a PR only after the human reviewed it and said to
- `verify`: drives the real app (generated by `create-verification-skill`, kept accurate by `maintain-verification-skill`)
- `eval`: quality evals and error analysis, for anything with fuzzy output (LLM features, ranking, search)
- `ponytail` (style), `ponytail-review` (diff review), `ponytail-audit` (whole repo)
- `blast-radius`: before touching shared code
- `typescript-best-practices`: auto-loads for .ts/.tsx
- `thermo-nuclear-code-quality-review`: harsh structural review; only the human starts it
