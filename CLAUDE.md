# Bee Loop

Concept prototype (for an Ithaca Holdings call) of a learning layer for Bumble's Bee + Plans: a voice debrief after a group hangout updates the user's preferences and next week's group Plan. Demo-quality, not production.

## Stack
Next.js 16 (App Router) + TypeScript + Tailwind v4. Next 16 differs from older versions: check `node_modules/next/dist/docs/` before using a Next API (see `AGENTS.md`). No database: demo state lives in browser localStorage; the user pool is generated by a seeded script. ElevenLabs Agents (`@elevenlabs/react`) for voice, Claude (`@anthropic-ai/sdk`, `claude-opus-5-5`, structured outputs) for extraction and the text fallback. Secrets (`ANTHROPIC_API_KEY`, `ELEVENLABS_API_KEY`, `ELEVENLABS_AGENT_ID`) live in `.env.local` / Vercel env vars, server-side only. Deployed on Vercel.

## Layout
- `src/lib/`: domain logic (matcher, profile updates, extraction schema, seed, prompts loader); `src/lib/server/` is server-only (Claude call, mode flag)
- `src/app/api/`: route handlers (`extract`, `chat`, `voice-session`)
- `src/components/`: UI (one page, several screens)
- `prompts/`: Bee's prompt and the extraction prompt (Markdown with `{{vars}}`)
- `fixtures/demo/`: Maya's recorded debrief + extraction
- `tests/` (Vitest), `e2e/` (Playwright), `evals/` (extraction quality, real API)
- `tickets/`, `evidence/` (screenshots from e2e)

## Commands
- `bash scripts/quick-check.sh`: fast checks (typecheck, lint). Runs after every edit.
- `bash scripts/verify.sh`: everything (quick checks, unit, build, e2e). Must pass before any task is done.
- `npm run dev` → http://localhost:3000 (copy `.env.example` to `.env.local` first)
- `npm run seed`: regenerate `src/data/users.json`; `npm run eval`: extraction eval (needs `ANTHROPIC_API_KEY`, ~3¢/case)

## Real data
No real data exists or may be used (no real people, no Bumble data, nothing scraped). Inputs are synthetic: `src/lib/seed.ts` (pool) and `fixtures/demo/` (the scripted debrief). Eval cases in `evals/cases/`; `evals/holdout/` is never shown to the agent (not yet populated).

## Test seams
- `DEMO_MODE=mock`: API routes return fixtures from `fixtures/demo/`, the voice call replays the recorded transcript. No network, no keys.
- `extractDebrief({ call })` takes the model call as a parameter so unit tests can script Claude's outputs.
Don't add new bypasses without asking.

## Review checklist (project-specific)
- API keys never reach the browser bundle or API responses; voice uses a signed URL from `/api/voice-session`.
- "Why" lines are templates filled from matcher inputs; the LLM never writes them.
- LLM output is untrusted: schema-validated, range-checked, `old_weight` ignored, step size capped.
- Demo-safe: `DEMO_MODE=mock` must run the full flow offline; every failure screen has a way forward.
- No Bumble logo or claims of affiliation; footer label stays.

## Definition of done
A task is done only when ALL of these hold:
1. `bash scripts/verify.sh` passes
2. You ran the `verify` skill and checked the evidence it produced (screenshots, output, logs)
3. Every verification scenario in the ticket is checked off with evidence (test name or evidence path)
4. The `ponytail-review` skill finds nothing left to fix, and the `reviewer-correctness` agent returned APPROVE

Never weaken, skip, or delete a test or eval case to get green. If a test looks wrong, stop and say why.
